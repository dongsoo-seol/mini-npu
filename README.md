# Mini NPU 시뮬레이터

## 1. 프로젝트 개요

코디세이 미션 3으로 개발한 Python 콘솔 애플리케이션이다.

입력 패턴과 필터의 같은 위치에 있는 값을 곱하고 모두 더하는 MAC 연산을 반복문으로 구현했다.

사용자 입력 분석과 JSON 일괄 분석을 지원하며, 점수·판정·성능 표와 결과 리포트를 출력한다.

실제 NPU 하드웨어를 구현하거나 필터를 학습하는 프로그램은 아니다.

## 2. 개발 환경

- 요구 환경: Python 3.8 이상
- 실제 검증 환경: Windows PowerShell, Python 3.12.10
- 외부 라이브러리 사용 없음
- json, pathlib, math, re, time 등 Python 표준 라이브러리 사용
- 자동 검증에는 unittest와 표준 라이브러리 사용
- NumPy, pandas와 벡터화 라이브러리 사용 없음

별도의 pip 설치 명령은 필요하지 않다.

## 3. 기능과 실행 흐름

### 사용자 입력 모드

```text
필터 A 입력
→ 필터 B 입력
→ 저장된 필터 출력·확인
→ 패턴 입력
→ 두 필터의 MAC 계산
→ A/B/판정 불가 출력
→ 3×3 성능 표
→ 메뉴 복귀
```

각 행은 공백으로 구분한 숫자 3개로 입력한다.

숫자 개수와 숫자 변환을 검사하고, 잘못된 행은 안내 후 다시 입력받는다.

정수와 실수를 사용할 수 있으며 NaN과 무한대는 거절한다.

### JSON 분석 모드

```text
필터와 패턴 로드·검증
→ 케이스별 MAC 점수·판정·PASS/FAIL
→ 네 크기의 성능 표
→ 전체 테스트 수·통과 수·실패 수
→ 실패 식별자와 사유 목록
→ 메뉴 복귀
```

원본 data.json은 다음 구조를 사용한다.

- filters: size_5, size_13, size_25
- 각 크기의 필터: cross, x
- patterns: size_N_idx 형태의 식별자
- 각 패턴: input, expected

식별자에서 N을 추출하고 해당 size_N 필터를 선택한다.

행·열 개수, 자료형, 숫자 값과 필수 항목을 검증한 뒤 Matrix로 변환한다.

케이스의 검증·계산 오류는 해당 케이스를 FAIL로 기록하고 다음 케이스를 계속 분석한다.

파일 전체를 읽거나 해석하지 못하면 분석 불가 사유를 안내하고 메뉴로 돌아간다.
이를 정상 분석의 0 FAIL로 표시하지 않는다.

## 4. MAC와 판정 정책

### MAC 계산

N×N의 모든 위치를 중첩 반복문으로 순회한다.

```text
누적값 = 누적값 + 입력값 × 필터값
```

일반적인 행렬 곱셈이 아니라 같은 위치의 곱을 모두 합산하는 연산이다.

Matrix는 특정 행·열의 값 저장과 조회를 제공한다.
필수 크기인 3×3, 5×5, 13×13, 25×25를 검증했다.

### 라벨 정규화

| 원본 표현 | 표준 라벨 |
|---|---|
| expected의 + | Cross |
| 필터 키 cross | Cross |
| expected와 필터 키의 x | X |

앞뒤 공백과 대소문자 차이도 처리한다.
표준 라벨 Cross와 X를 다시 입력해도 같은 표준값을 반환한다.

알 수 없는 라벨, 정규화 후 중복된 필터와 필수 필터 누락은 오류로 처리한다.

### epsilon 동점 처리

```text
epsilon = 1e-9
abs(점수 A - 점수 B) < epsilon이면 동점
```

동점 검사를 먼저 수행하고, 동점이 아니면 높은 점수를 선택한다.
차이가 epsilon과 같으면 동점이 아니다.

| 모드 | 우세 판정 | 동점 표시 |
|---|---|---|
| 사용자 입력 | A 또는 B | 판정 불가 |
| JSON 분석 | Cross 또는 X | UNDECIDED |

사용자 입력의 필터 A가 반드시 십자가라고 가정하지 않는다.

JSON 분석에서는 Cross 점수와 X 점수를 비교하고, 정규화한 expected와 판정이 같으면 PASS, 다르면 FAIL이다.

UNDECIDED는 모양 라벨이 아니라 판정 보류 상태이다.

## 5. 성능 분석

### 측정 방법

- time.perf_counter() 사용
- 필터 하나의 MAC 함수 호출 시간 측정
- 준비 실행 1회는 평균에서 제외
- 이후 크기별 10회 측정한 1회 평균 사용
- 초 단위 측정값에 1000을 곱하여 ms로 변환
- 배열 준비, 파일 읽기, 사용자 입력과 출력 시간 제외
- MAC 함수 내부의 검사와 값 조회 비용은 포함

사용자 입력 모드는 실제 입력 패턴과 필터 A를 측정한다.

JSON 모드의 크기별 비교에는 모든 값이 1.0인 공통 측정용 배열을 사용한다.
이 측정 자료는 원본 판정과 PASS/FAIL 계산에 사용하지 않는다.

### 저장한 실제 측정값

| 크기 | 평균 시간(ms) | 연산 횟수(N^2) | 측정 횟수 |
|---|---:|---:|---:|
| 3×3 | 0.011840 | 9 | 10 |
| 5×5 | 0.028900 | 25 | 10 |
| 13×13 | 0.183770 | 169 | 10 |
| 25×25 | 1.154100 | 625 | 10 |

N^2는 N×N을 뜻하며, 필터 하나를 한 번 적용하는 MAC 횟수이다.

표는 결과 파일 저장 당시의 기록이다.
시간은 실행 환경과 컴퓨터 상태에 따라 달라지며, 같은 숫자의 재현을 보장하지 않는다.

화면과 표에는 소수점 아래 6자리로 표시하고, 결과 파일에는 평균 시간의 원래 반환값을 저장했다.

- 측정 원본: [성능 결과 JSON](docs/08-performance-results.json)
- 측정 설명: [8단계 수행 기록](docs/08-performance.md)

## 6. 실행 방법

main.py와 제공된 data.json을 같은 폴더에 둔다.

터미널에서 main.py가 있는 폴더로 이동하여 실행한다.

```powershell
python main.py
```

| 메뉴 | 동작 |
|---|---|
| 1 | 3×3 사용자 입력 분석 |
| 2 | data.json 일괄 분석 |
| 0 | 종료 |

분석 후에는 메뉴로 돌아간다.
잘못된 메뉴 입력은 안내 후 다시 입력받는다.

data.json의 기본 경로는 현재 작업 위치가 아니라 main.py의 위치를 기준으로 처리한다.

입력 종료 또는 Ctrl+C 발생 시 안내 후 종료한다.

## 8. 결과 리포트

### 원본 데이터 분석 결과

| 케이스 | Cross 점수 | X 점수 | 판정 | 기대값 | 결과 |
|---|---:|---:|---|---|---|
| size_5_1 | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.700000000000008 | X | X | PASS |
| size_13_2 | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

전체 6개, 통과 3개, 실패 3개로 집계가 일치한다.

### 실패 원인과 복잡도 분석

1. 원본 expected의 +와 x를 Cross와 X로 정규화하여 비교했다.
2. 필터 키도 같은 표준 라벨로 통일하여 표현 차이에 따른 잘못된 비교를 방지했다.
3. 두 점수 차이의 절댓값이 1e-9보다 작으면 UNDECIDED로 판정했다.
4. size_5_1은 0.9와 0.8999999999999999의 차이가 epsilon보다 작아 동점이 되었다.
5. size_5_1의 기대값은 X이므로 동점 판정과 일치하지 않아 FAIL이다.
6. size_13_2도 7.499999999999997과 7.5의 차이가 epsilon보다 작고 기대값은 Cross이므로 FAIL이다.
7. size_25_1도 4.9와 4.899999999999999의 차이가 epsilon보다 작고 기대값은 X이므로 FAIL이다.
8. 나머지 세 케이스는 표준 라벨 판정이 기대값과 일치하여 PASS이다.
9. 이번 원본 분석에서는 구조 오류나 계산 불가로 실패한 케이스는 없었다.
10. PASS를 늘리기 위해 원본 데이터나 epsilon을 변경하지 않았다.
11. 필터 하나의 MAC 계산은 N개 행과 각 행의 N개 열을 순회하므로 N²회의 곱셈·누적을 수행한다.
12. 따라서 필터 하나의 시간 복잡도는 O(N²)이며, 두 필터를 적용해도 고정된 상수배이므로 O(N²)이다.
13. 저장한 성능 표에서는 위치 수가 9에서 625로 증가하면서 평균 시간도 증가했다.
14. 실제 시간 비율은 연산 횟수 비율과 정확히 같지 않으며 Python 호출 비용과 실행 환경 등의 영향을 받는다.
15. 입력·출력·파일 읽기·배열 준비는 측정에서 제외했지만 MAC 함수 내부의 검사와 값 조회 비용은 포함했다.
16. 배열 저장 공간은 O(N²)이고 MAC 함수 자체의 누적값·반복 변수 등 추가 공간은 O(1)이다.
17. 자동 검증 62개 통과는 원본의 FAIL이 사라졌다는 뜻이 아니라, 세 FAIL을 포함한 동작이 정책에 맞는지 확인했다는 뜻이다.

- 성능 원본: [측정 결과](docs/08-performance-results.json)

## 9. 재현 방법

### 사용자 입력 모드

프로그램을 실행하고 메뉴 1을 선택한다.

필터 A에 다음 세 행을 한 줄씩 입력한다.

```text
0 1 0
1 1 1
0 1 0
```

필터 B에 다음 세 행을 입력한다.

```text
1 0 1
0 1 0
1 0 1
```

저장된 필터를 확인한 뒤, 패턴에 다음 세 행을 입력한다.

```text
0 1 0
1 1 1
0 1 0
```

예상 결과:

```text
필터 A MAC 점수: 5
필터 B MAC 점수: 1
판정 결과: A
```

이어서 실제 입력 패턴과 필터 A의 3×3 성능 표가 출력되고 메뉴로 돌아간다.

같은 필터에서 X 패턴을 입력하면 점수 1과 5, 판정 B이다.
모두 0인 패턴을 입력하면 점수 0과 0, 판정 불가이다.

### JSON 분석 모드

메뉴 2를 선택한다.

케이스별 결과, 네 크기의 성능 표, 전체 요약과 실패 목록이 순서대로 출력된다.

원본 기준 예상 집계:

```text
전체 테스트 수: 6
통과 수: 3
실패 수: 3
```

실패 목록은 size_5_1, size_13_2, size_25_1이다.

### 의도적 오류 검증

사용자 입력에서 숫자 부족·초과, 문자와 빈 입력을 넣으면 해당 행을 다시 입력받아야 한다.

JSON 오류 검증은 원본을 보존하고 별도 시험용 자료로 수행한다.
자동 검증에는 크기 불일치, 누락 항목, 라벨 오류, 파일 오류와 다음 케이스 계속 처리를 포함했다.

## 11. 구현의 한계

- 실제 NPU의 병렬 처리 성능을 재현하지 않는다.
- 필터를 자동으로 학습하지 않는다.
- MAC 점수는 확률이나 일반적인 그림 유사도 지표가 아니다.
- 위치별 점수 비교이므로 이동·회전·잡음에 대한 일반적인 인식을 보장하지 않는다.
- 절대 허용오차 정책에 따라 기대값과 다른 동점 판정이 나올 수 있다.
- 짧은 실행 시간은 환경 영향을 받으므로 단일 측정만으로 성능을 일반화하지 않는다.
