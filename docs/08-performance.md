# 8단계. MAC 성능 측정과 출력 연결

## 1. 수행 목표

크기별 MAC 계산을 최소 10회 측정하여 평균 시간(ms)을 구한다.

사용자 모드와 JSON 모드의 지정된 위치에 성능 표를 출력한다.

## 2. 학습 목표

- 시간 측정 구간을 명확히 정한다.
- 준비 실행과 실제 측정 횟수를 구분한다.
- 초를 ms로 변환한다.
- 이론적인 연산 횟수와 실제 실행 시간을 구분한다.
- 실제 측정값과 자동 검증용 가상 시계 값을 구분한다.

## 3. 구현한 함수

| 함수 | 역할 |
|---|---|
| measure_mac_time() | MAC 호출을 반복 측정하여 1회 평균 반환 |
| make_benchmark_pair() | 공통 조건의 측정용 배열 준비 |
| benchmark_sizes() | 네 크기의 측정 결과 생성 |
| print_performance_table() | 측정 결과를 표로 출력 |

run_manual_mode()와 run_json_mode()에 성능 표 출력을 연결했다.

## 4. 측정 기준

필터 하나를 한 번 적용하는 MAC 함수 호출을 측정한다.

측정 순서:

1. 입력 배열과 필터를 미리 준비한다.
2. 측정 횟수가 정수이며 최소 10회인지 확인한다.
3. MAC를 1회 준비 실행한다.
4. 준비 실행 시간은 평균에 포함하지 않는다.
5. time.perf_counter()로 MAC 호출 구간을 10회 측정한다.
6. 측정 시간의 합을 반복 횟수로 나눈다.
7. 1000을 곱해 초를 ms로 변환한다.

평균 계산식:

```text
평균 시간(ms) = 측정 시간 합계(초) ÷ 측정 횟수 × 1000
```

기본 설정에서는 준비 실행 1회와 측정 10회로 MAC를 총 11회 호출한다.
평균 시간은 측정한 10회만 사용한다.

## 5. 포함·제외한 작업

측정에 포함:

- MAC 함수 호출
- 함수 내부의 자료형·크기 확인
- 반복문과 get_value() 호출
- 위치별 곱셈과 누적
- 계산 결과 확인과 반환

측정에서 제외:

- 사용자 입력
- JSON 파일 읽기
- 배열 생성과 값 준비
- 결과 표와 화면 출력

따라서 이 값은 Python으로 구현한 MAC 함수의 호출 시간이다.
곱셈 명령만의 실행 시간이나 실제 NPU 하드웨어 성능을 뜻하지 않는다.

## 6. 모드별 측정 자료

### 사용자 입력 모드

실제로 입력한 패턴과 필터 A를 측정한다.

표의 자료 설명:

```text
사용자 입력 패턴 / 필터 A
```

출력 순서:

```text
필터 입력과 저장 확인
→ 패턴 입력
→ MAC 점수와 판정
→ 3×3 성능 표
```

### JSON 분석 모드

크기별 비교에는 모든 값이 1.0인 공통 측정용 배열을 사용한다.

3×3, 5×5, 13×13, 25×25 모두 같은 숫자 조건으로 준비한다.
측정용 자료는 제공된 data.json을 변경하지 않는다.

원본 판정과 PASS/FAIL은 원본 자료로 계산한다.
성능 측정에 별도 자료를 사용했다고 실패 케이스를 PASS로 바꾸지 않는다.
출력 순서:

```text
원본 케이스별 결과
→ 네 크기의 성능 표
→ 전체 집계
→ 실패 케이스 목록
```

## 7. 저장한 실제 측정 결과

결과 파일:

```text
docs/08-performance-results.json
```

아래 표는 해당 파일을 저장한 실행에서 출력한 값이다.
화면과 문서에는 소수점 아래 6자리로 표시했다.
JSON에는 평균 시간의 원래 반환값을 저장했다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) | 측정 횟수 |
|---|---:|---:|---:|
| 3×3 | 0.011840 | 9 | 10 |
| 5×5 | 0.028900 | 25 | 10 |
| 13×13 | 0.183770 | 169 | 10 |
| 25×25 | 1.154100 | 625 | 10 |

측정 자료는 모든 값이 1.0인 공통 측정용 배열이다.

## 8. 성능 표 해석

N×N 배열의 모든 위치를 순회하므로 필터 하나의 MAC 횟수는 N²이다.

곱셈을 N²회 수행하고, 0으로 시작한 누적값에 결과를 N²회 더한다.

크기가 3에서 25로 증가하면 위치 수는 9에서 625로 증가한다.

이번 측정에서는 배열 크기 증가에 따라 평균 시간도 증가했다.

다만 시간 비율이 연산 횟수 비율과 정확히 같지는 않았다.

Python 함수 호출 비용, 실행 환경과 운영체제의 작업 상태 등이 측정값에 영향을 줄 수 있다.

작은 배열의 짧은 계산은 측정 변동의 영향을 받기 쉽다.

단일 실행의 시간만으로 모든 환경에서 같은 속도가 나온다고 일반화하지 않는다.

사용자 모드의 실제 입력과 공통 측정용 배열은 조건이 다르므로 시간을 단순 비교하지 않는다.

## 9. 시간·공간 복잡도

필터 하나의 MAC 시간 복잡도는 O(N²)이다.

두 필터를 적용해도 필터 수가 고정되어 있으므로 O(N²)이다.

입력과 필터 배열 자체의 저장 공간은 O(N²)이다.

MAC 함수의 누적값과 반복 변수 등 추가 공간은 O(1)이다.

benchmark_sizes()의 배열 준비에도 크기별 O(N²) 작업이 필요하지만, 이를 MAC 시간 측정 구간에서는 제외했다.

## 10. 자동 검증

test_performance.py에 8개 테스트를 작성했다.

| 테스트 | 확인 내용 |
|---|---|
| test_average_ms_and_repetitions | 준비 실행 제외, 10회 평균과 ms 환산 |
| test_invalid_repetitions | 정수·최소 10회 조건 |
| test_invalid_pair_before_timing | 잘못된 배열을 측정 전에 거절 |
| test_benchmark_arrays | 크기별 동일 숫자 조건과 배열 독립성 |
| test_required_sizes | 네 크기의 실제 측정값과 N² |
| test_table_output | 필수 표 항목과 시간 표시 |
| test_manual_performance_order | 실제 입력·필터 A 사용과 판정 후 출력 |
| test_json_performance_order | 케이스 결과와 전체 요약 사이의 표 출력 |

시간 환산 검사에는 가상 시계를 사용했다.
가상 시계의 결과를 실제 성능 표에 사용하지 않았다.
